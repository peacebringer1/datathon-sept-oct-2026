Каталог `data` и вообще датасеты лучше не заливать в репозиторий. Пусть находятся только локально.

В файл [renderer.js](frontend/renderer.js) и в вообще какие-либо не вставляйте личные данные, по типу API ключей к сервисам.

## ИИ-помощник

Чат, анализ графиков и аналитические наблюдения используют Claude через Anthropic API. Введите ключ Anthropic в меню ⚙️ приложения. Он сохраняется зашифрованным средствами Electron в локальном хранилище пользователя и не записывается в исходный код, настройки проекта или Git. Кнопка удаления убирает сохранённый ключ. Не вставляйте секрет в исходные файлы и не отправляйте его в чат или репозиторий.

Запросы к Claude выполняются только локальным Flask backend; ключ не передаётся renderer-компонентам. Без настроенного ключа AI-функции сообщают об этом, а не подменяют анализ обычной SQL-выборкой. Статус подключения проверяется через Anthropic API. По умолчанию используется модель `claude-sonnet-5-5`; при необходимости её можно переопределить переменной окружения `CLAUDE_MODEL` до запуска приложения.

Блок наблюдений вызывает Claude для выбранного показателя и передаёт ограниченный набор агрегированных значений региона и года. Ответ проверяется на формат перед показом. Результат кэшируется в памяти backend на пять минут; при ошибке API интерфейс показывает сообщение, а не фиктивный успешный результат.

Помощник читает локальную `database.sqlite` через read-only аналитические запросы. База создаётся из CSV в `data/raw/` скриптом `clean_to_db.py` и хранит агрегаты по показателю, году и региону; исходные дополнительные столбцы CSV в таблицу `demographics` не входят.

Перед заменой базы скрипт сохраняет отчёт `database_import_report.json`: в нём указаны прочитанные, принятые и отброшенные строки, причины отбраковки и пропущенные файлы. Пустые или некорректные значения больше не преобразуются в нули; строки с нераспознанным регионом и некорректными полями учитываются в отчёте. Если ни одной корректной строки не осталось, импорт завершается без изменения существующей базы.

Повторяющиеся записи с одинаковыми показателем, годом и регионом по умолчанию блокируют импорт: тип агрегирования из имени показателя надёжно определить нельзя. Предпочтительно задавать отдельную политику каждому повторяющемуся показателю через локальный JSON-файл:

```shell
python clean_to_db.py --aggregation-map aggregation.json
```

Пример содержимого файла:

```json
{
  "Численность населения": "sum",
  "Средний размер домохозяйства": "mean"
}
```

Поддерживаются `sum`, `mean`, `min`, `max` и `first`; `first` использует первую запись в стабильном порядке CSV-файлов и строк. Политика применяется только к дублям указанного показателя. Для показателей без правила импорт остановится; общий `--aggregation sum` доступен только если один режим подходит всем показателям-дублям. Чтобы прервать импорт при любых отброшенных строках или пропущенных файлах, добавьте `--strict`. Для пороговой проверки можно задать `--max-discarded-fraction 0.01` (не более 1% отброшенных строк в прочитанных файлах). Причины отбраковки могут пересекаться; число `rows_discarded` считает уникальные строки. Проверки выполняются до обновления базы, а публикация новой таблицы проходит транзакционно.

## Запуск и сборка приложения

### Веб-режим (локальный предпросмотр)

Веб-режим показывает четыре набора D002, D004, D006 и D008 в обычном браузере. Для входа задаются отдельные секреты доступа; AI-ассистент остаётся отключённым, пока не будет настроен защищённый AI-сервис. Исходные наборы остаются локальными и не добавляются в Git.

```shell
cd DataHackathon/frontend
python -m pip install -r requirements.txt
npm ci
JURY_ACCESS_CODE="$(openssl rand -hex 12)" \
WEB_SESSION_SECRET="$(openssl rand -hex 32)" \
WEB_COOKIE_SECURE=0 \
python web_server.py
```

Откройте `http://127.0.0.1:8000` и введите сгенерированный код доступа. Сервер проверяет наличие CSV во всех четырёх папках. Этот локальный запуск виден только на текущем компьютере; чтобы выдать жюри публичную ссылку, потребуется развернуть web-сервис на хостинге, загрузить туда датасеты и задать новые секреты в настройках хостинга. Не используйте локальные тестовые коды на публичном сайте.

Для запуска из исходников в `DataHackathon/frontend/` установите зависимости командой `npm ci` и выполните `npm start`. ECharts включён в локальные npm-зависимости приложения; Google Fonts/CDN не используются, шрифт выбирается из системных шрифтов компьютера. Импорт XLSX выполняется локальным Python backend. Установщики включают этот backend как исполняемый файл и не требуют установленного Python. Интернет после установки приложения нужен только AI-функциям Claude.

Сборки создаются на соответствующих ОС:

- macOS: `npm run build:mac` создаёт DMG и ZIP для архитектуры текущего Mac.
- Windows x64: `npm run build:win` создаёт NSIS-установщик `.exe`.

Для выпуска Windows-сборки выполните Windows-команду на Windows-компьютере; macOS-сборку аналогично создавайте на Mac. Backend, собранный PyInstaller, привязан к ОС и архитектуре сборочного компьютера, поэтому Windows `.exe` нельзя получить из этой конфигурации на Mac. Перед сборкой установите backend-зависимости по инструкции ниже и положите подготовленный `DataHackathon/database.sqlite` в корень проекта. База должна содержать импортированные наборы D002, D004, D006 и D008.

Установщики включают один файл `database.sqlite`; папка `data/sinte` для сборки и запуска настольного приложения не требуется. При первом запуске приложение копирует базу в пользовательскую папку данных, откуда backend читает четыре импортированных набора. Если в пользовательской папке осталась база от старой версии без этих наборов, приложение сохраняет её как резервную копию и устанавливает актуальную. Сам файл базы не добавляется в Git. AI-функции пока требуют ключ Anthropic в настройках. Чтобы жюри могло пользоваться ими без личного ключа, нужно отдельно развернуть защищённый AI backend и хранить ключ Anthropic в секретах его хостинга.

Проверки: из корня репозитория запустите `python -m unittest discover -s DataHackathon/tests -p "test_*.py"`. Из `DataHackathon/frontend/` выполните `npm run test:frontend`. API принимает `page` от 1 до 100000 и `limit` от 1 до 5000; остальные значения возвращают HTTP 400. CORS разрешён только Electron file-origin и HTTP(S) loopback-origin.

## Анализ и очистка пользовательских файлов

Пункт «Анализ данных» в боковом меню открывает Data Analyzer в отдельной встроенной странице. Electron запускает для него локальный FastAPI-сервер отдельно от Flask API аналитики Казахстана.

Модули `core/` из `DataAnalyzer_v1.8.3.rar` должны быть распакованы в корень проекта рядом с `server.py`. HTML интерфейс анализатора находится в корневом `index.html` и отдаётся этим сервером; архив и сами загружаемые CSV/XLSX файлы не нужно помещать в Git.

Выберите датасет в Data Analyzer, затем нажмите «Демография»: четыре основных графика, списки показателей и годов и таблица будут использовать только этот выбранный набор вместо `database.sqlite`. Таблицы с колонками показателя, года, области и значения строятся напрямую; для широких опросных CSV/XLSX анализатор автоматически берёт числовые столбцы-вопросы и строит распределение ответов, распознавая год, если он указан в данных. Данные передаются локально между приложениями и хранятся в памяти Flask, исходная база не изменяется. Кнопка «Загрузить базу демографии» добавляет локальную таблицу `demographics` в список датасетов анализатора. После удаления выбранного набора можно выбрать другой — дашборд переключится на новый при возврате в «Демография».

Для обоих backend используйте окружение проекта `.venv` и установите зависимости из `backend/requirements.txt`. При добавлении новых модулей из архива оставляйте исходные CSV/XLSX на компьютере пользователя: загруженные наборы хранятся только в памяти текущего процесса.
